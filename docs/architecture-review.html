Cost Realism

No EC2/RDS/ECS. Good.

Not approvable as written:

  • No usage assumptions (<1000 users, extracts/user/month, image GB, PostHog events).
  • Free tiers treated as unlimited. Need ceilings: Vercel Hobby bandwidth + function duration, Supabase 500MB / 1GB storage / pause-on-inactivity, PostHog free events + replay, Sentry free errors, GitHub Actions minutes on a public repo.
  • xAI is the only real variable cost and is unpriced. Need a unit cost × assumed billable extracts (cache-hit vs miss, text vs vision).
  • Upgrade path is “buy Pro.” Fine once triggers exist (DB size, function timeout, replay volume).

Assumptions at Risk

Mandatory audit. Zero of these are validated in production.

  1. Blocker — Vercel Hobby duration vs extract. Pipeline allows an 8s page fetch then JSON-LD parse or xAI text/vision. Hobby serverless duration is typically 10s. A cache miss on a slow blog or any LLM call will 504. Unvalidated. Must choose: Pro / longer maxDuration, background extract + inbox poll, or a documented timeout/retry model. Silent assumption that “route handlers on Vercel” can run this pipeline is unsafe.

  2. Blocker — Architecture-as-delta is a complete spec. False. Sketch + four bullets is not a schema an engineer can migrate. After 15 sketch deltas and proto drift, the locked model must be restated in Architecture.

  3. Risk — No-headless fetch gets a cookable recipe. Many recipe and almost all social pages are JS-rendered. Server fetch + linkedom will miss schema.org that only appears after hydration. Fallback is xAI on raw HTML/oEmbed — quality unproven. Same family as the PRD-reviewer extraction-feasibility warning; v1.1 is more honest (no Whisper) but still unspiked.

  4. Risk — Social video without Whisper is “good enough.” oEmbed title/description + optional YouTube timedtext. TikTok/Reels/Instagram often have no captions and a useless description. Confirm-or-manual is the escape hatch; the hero capture path may still yield needs_care on most shares. Alpha spike still required.

  5. Risk — Global full-text recipes + default-Global capture. PRD-reviewer already flagged copyright: private/peer-share justification does not cover a public catalogue of full instructions. v1.1 makes this more acute (Confirm defaults Global so Browse grows). No legal/ToS/source-link policy in Architecture.

  6. Risk — Client lens on a global cached home payload. Correct for V1 cost. For you/Discover only reorders the same ≤16 cards. If liked cuisines are absent from that trending/popular slice, For you is empty even when the catalogue has matches. Design says empty+clear-filters is OK; product risk if “For you” looks broken on day one.

  7. Risk — engagementScore placeholder shipped as Popular. Documented as proto-parity. Fine for alpha if labelled. Do not treat the formula as tuned.

  8. Risk — Rate limit unspecified. Sketch deferred numbers to architecture. Still missing. Without a number, C3 cannot implement a 429 that matches product copy.

  9. Risk — iOS Shortcut / Android PWA install as primary capture. PRD already flagged unvalidated setup. Architecture does not design the unauthenticated share-target → login → resume path.

  10. Risk — Multi-user catalogue/fork model still unvalidated. PRD §4.2. Architecture does not change that. Beta (2–6 people) remains make-or-break.

  11. Observation — Profile.tasteSignals still open. Correctly not invented. Taste graph still writes cuisines_liked only for V1 unless Venkat locks the column.

  12. Observation — PRD.md is stale. Pantry, named-recipient share, Playlist/Station, produce/pantry, Follow, idea pool still in PRD. Engineers must build from Design v1.6 + a rewritten Architecture, not the PRD. Out of scope for this rewrite, but a footgun.

  13. Observation — design-reviewer was not invoked on Design v1.6. Process note, not an architecture defect. Product owner chose this gate anyway.
