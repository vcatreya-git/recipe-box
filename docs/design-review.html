Design Review — Recipe Box

Reviewed: 2026-08-16
Scope: Design v1.6 + prototype of record Prototype-v2.html (Phase 7c-style gate). Architecture v1.1 already exists — this review does not reopen architecture from scratch. Roadmap is not in the project folder (skipped).

VERDICT: APPROVED WITH CHANGES

The click-through is the product. The locked late decisions (link-only share, capture defaults Global, Browse-add stays personal, generate is a draft until Shopping list then silent archive, Profile Support) are implemented and usable. This is not a rewrite. Four patches are required before treating the freeze as clean: S5 still teaches paste-as-primary, Flow 2 has no receive screen, Buy me a coffee is toast-only, and leftover named-share screens are still registered.

COVERAGE

  • [x] Every P0 user story from the PRD has a defined flow — pass with caveat. Current-model P0s (capture/confirm, Browse-add, globe, generate→shop→archive, link send, collections, Profile Support) have flows in Design §1. PRD still describes the superseded Playlist/Station + named-recipient + pantry model; Design correctly follows the later 00-Decision-Log, not the stale PRD. Gap: opening a share link (the receive half of Flow 2) is stated in copy and missing as a screen.
  • [x] Every flow has a defined entry point, steps, and exit — pass for send/cook/generate; fail for share receive. Flow 2: “Anyone with the link can view and add their own copy” has no entry screen after S11 was removed. Flow 1 names OS share-sheet as primary entry; S5 in the proto does not.
  • [x] Every screen is defined with purpose, key elements, and navigation — fail (thin). Design §4 is a delta stub (1–3 lines per screen). An engineer cannot build S5 share-sheet setup, the public token page, rate-limit/blocked errors, or empty-generate from Design alone. The proto + Architecture carry the real spec.
  • [x] Edge cases and error states are defined for each flow — fail. v1.6 dropped the consolidated edge-case table. Rate-limit, blocked, failed extract, unauthenticated share-sheet POST, and empty-box generate are implemented or implied in the proto/Architecture, not specified in Design.
  • [x] Empty states are defined for every screen that can have no data — pass in proto, partial in Design. Proto has empty Box (hero), Inbox, Plan, Shopping list, Browse filter-empty, collection-empty. Design only calls out S8 empty and Browse sparse.

CLARITY

  • [x] Screen definitions are specific enough for an engineer to build from — fail as a standalone doc; pass if proto is the source of record. v1.6 banner says the click-through is the product. That is honest. It is not a 7a-complete spec.
  • [x] Navigation between screens is unambiguous — pass. 4-tab Browse · My recipes · This Week · Profile. FAB only on a non-empty Box. Shopping list from This Week or S8. Back targets exist for the live screens.
  • [x] Decision points in flows are clearly defined — pass. Global vs Personal at confirm; mix-in and grocery-saving as This Week switches; draft vs committed at Shopping list; globe is one-way; Browse-add cannot re-publish.
  • [x] No screens are implied but undefined — fail. Public recipe / week / collection / list link view is implied by Flow 2 and missing from the inventory. iOS Shortcut / Android PWA-install prompting is implied by P0 share-sheet and missing from S1/S5.

ARCHITECTURE READINESS

  • [x] Handoff notes for architecture are present and cover data, APIs, and state — pass (adequate, not lush). Design §7: RLS (owner Box, global readable, share tokens public-by-link), Browse home as one payload, generate as deterministic TypeScript (no LLM), extract server-only (tools in Architecture), aisle computed not stored. Enough to not block this gate. Architecture already has a v1.1 draft.
  • [x] Real-time or async requirements are called out — pass. Extract is server-side / deferred in the proto (inbox extracting → ready). No sockets. Push still out of scope.
  • [x] Third-party integrations implied by the design are identified — pass by pointer. Design defers extract tools to Architecture (schema.org → oEmbed/captions → xAI grok-4.5; no Whisper). Feedback / Buy me a coffee destinations are not named.

ISSUES FOUND

  1. S5 contradicts share-sheet-as-P0. Design Flow 1 and the 2026-08-16 decision say OS share-sheet is the primary capture path. The proto lede is “copy the link, come back, paste”; footer: “Sharing straight from TikTok/YouTube’s own share sheet isn’t built yet… Paste-link above is the actual way in for now.” That un-teaches the P0 path. A HTML proto cannot register a real share target — it can simulate one (they already simulate a clipboard link).
  2. Flow 2 receive is undefined. S11 Incoming Shares was correctly removed from the product surface. Nothing replaced it. No public token view, no “Open this link” simulate, no add-my-copy from a link. Send is a dead letter for a second person.
  3. Buy me a coffee is a toast-only dead end (openCoffee() → toast, no sheet, no URL, no state change). Gate rule: every button must navigate or change state.
  4. Leftover S10 / S11 still registered. scr-visibility (named people + CONTACTS) and scr-shares (seeded Meera/Devika/Nils inbox) still have renderers, headers, back targets, and seed data. No live nav calls them (openVisibilityFromDetail / openShares have no onclick). Unreachable is not the same as removed — a future pass can re-wire a contradiction of the decision log.
  5. Design.md v1.6 dropped 7a-mandatory completeness. No User Control Flows section, no edge-case table, screen defs are deltas. Acceptable only if the proto is explicitly the spec and implied screens are still listed. The receive screen was not listed.
  6. Share-sheet setup UX never designed. Sketch delta #7 deferred Android PWA-install / iOS Shortcut prompting to S1/S5. Neither Design nor the proto shows that one-time setup. Without it, the P0 path has no first-run.
  7. Collection picker copy still says “never shared” while collection header share mints a link. Design v1.6 + the 2026-08-16 share decision allow collection links. The sheet note is stale.

Non-blocking observations (not required for this verdict):

  • PRD.md is a full version behind the freeze (Playlist/Station, named share, pantry). Do not block Design on a PRD rewrite.
  • Profile.tasteSignals remains an open sketch question; proto writes it on retune. Fine to leave unlocked.
  • Proto header comments still say “taste is always last / slots then taste”; runtime order matches Design (diet → taste → usual week if planning).
  • No admin UI — matches “no moderation queue / User.blocked is a DB runbook.”
  • No paywall in V1 — nothing to mismatch.
  • Multi-select “None” mutual exclusion: N/A (no None option on intents or diet).
  • Visual hierarchy: .grouphead (surface2, 14px/700) is distinct from .vcard cards.

REQUIRED CHANGES

  1. S5 — teach share-sheet as primary. Lead with “Share to Recipe Box” (Android share target / iOS Shortcut). Add a Simulate: shared from TikTok/Instagram action that lands in Inbox the same as a share-target POST. Relabel paste / screenshot / type-name as fallback. Delete the “isn’t built yet / paste is the actual way” footer. One line on S1 or S5 for the one-time setup (install PWA / install Shortcut).
  2. Define and prototype the link-receive screen. New inventory row (e.g. S20 Shared view): unauthenticated view of recipe / week+list / collection; primary “Add to my recipes” (personal fork, same confirm-or-quick-add as Browse); signed-out user can view, add requires account. From the share sheet, add Open this link so the receive path is clickable. Update Flow 2 and the mermaid.
  3. Buy me a coffee must do something real. Open a sheet with a URL + Copy / Open, or window.open a placeholder BMC URL. Toast-only is a blocker-class dead end; this is a one-function fix.
  4. Delete leftover named-share surface. Remove scr-visibility, scr-shares, sharesIncoming seed, openVisibilityFromDetail, openShares, renderVisibility, renderShares from SCREEN_RENDERERS / HEADERS / BACK_TARGETS. Globe + link sheet stay. Do not leave a named-people picker in the file.
  5. Align collection-share copy. Picker helper should not say collections are “never shared” if a collection can mint a view link. “Adding a collection does not publish its recipes to Browse” is the accurate sentence.

Items 1–4 are the bar for a clean freeze. Item 5 is copy. Do not rewrite Design as a 7a novel — patch the missing receive screen and the S5 setup line, then stop.

WHAT'S GOOD

  1. Generate is honest. Draft until Shopping list, silent archive after commit, unfilled seats with Browse / My recipes CTAs (not capture), mix-in as a labelled where switch, Surprise as a seat. Matches the owner’s “shape is the week” decision.
  2. Ownership rules are consistent in the live UI. Capture defaults Global; Browse-add and swap-from-Browse stay personal and cannot be re-globed; globe is one-way. That is the catalogue-growth rule without republish noise.
  3. The 4-tab IA holds. No hidden dashboard, no pantry tab, Support quiet at the top of Profile, chips wrap, 3-up cards, For you / Discover as a lens on one home payload. The proto and Design v1.6 agree on the product the owner froze.

ASSUMPTIONS AT RISK

  1. Risk — Share-sheet adoption. P0 capture on iOS is a one-time Shortcut install; on Android a PWA install. Neither is designed or simulated. PRD §13.2 already flagged Shortcut completion as unvalidated. If users never set it up, the product they were promised is paste — which the owner rejected twice. Severity: risk (not a design-structure blocker; it is the main activation risk).
  2. Risk — Capture defaults Global. Every extract, including thin social-video ones, is one tap from the public catalogue. PRD review already flagged global-tier full-text copyright as closer to redistribution than “personal/peer-shared.” Default-Global raises the volume of that exposure. needs_care is non-blocking. Severity: risk.
  3. Risk — Empty Box after onboarding. Real onboarding lands on an empty library. Generate then produces Unfilled seats unless mix-in is on or the user fills from Browse. First-week success assumes a seeded catalogue and that a new user will pick into empty seats. Unvalidated. Severity: risk.
  4. Risk — Link receive is unspecified. “Anyone with the link can view and add” assumes a public token page, an auth gate for add, and a personal fork. None of that is designed. Architecture already has GET /api/shared-plan/:token; recipe/collection equivalents are implied. Severity: risk (required change #2).
  5. Risk — Social-video extract still unproven. Proto fakes a successful extract. V1 never ran caption/audio. Architecture dropped Whisper; xAI vision/text is the bet. Same P0 feasibility gap the PRD reviewer logged. Severity: risk.
  6. Risk — Cook marks are optional with no nudge. North Star is cooked-in-window. Marks live only on the meal card. Absence is not a skip (correct), but then the metric under-counts if people do not return. Same 7a finding, still true. Severity: risk.
  7. Risk — Catalogue cold start. Growth plan is “capture defaults Global.” If Personal opt-out is common (especially after the low-confidence banner), Browse stays a seed file. Proto catalogue is demonstration content, not a launch plan. Severity: risk.
  8. Observation — tasteSignals unlocked. Proto persists a soft signal; sketch left the column open. Do not invent a lock in this review.
  9. Observation — No willingness-to-pay / Support conversion. Feedback and coffee are present; neither is a business model. Fine for V1.

No assumption here is a verdict blocker. The required changes above are execution holes, not “the model is wrong.”

INSTRUCTION GAP CHECK

Flag: YES (narrow).

Proto-freeze rewrites of Design were allowed to become a delta memo. That dropped the 7a-required User Control Flows section, edge-case table, and full screen specs — and nothing in the freeze prompt said “if you remove Incoming Shares, you must define the replacement receive screen.” The dead-end coffee button and leftover S10/S11 are execution on this file (design-agent already knows every onclick must do something real; they left two retired screens in SCREEN_RENDERERS).

Suggested instruction add, not a workflow rewrite: When a receive inbox is deleted in favor of links, the public token view is a P0 screen, not an implied web page. When Design is rewritten from a proto freeze, keep User Control Flows + edge/empty/error states, even if screen bodies stay short. Share-sheet-primary products must simulate the share-target path in the proto; they must not teach the fallback as the real way in.

P0 TRACE (reviewer notes)

  • Onboarding: Intent (multi, no None) → diet (stance required) → taste (resume-on-back, Continue gated without a “1 of 3” label) → usual week only if planning → empty My recipes. Matches Design Flow 0. Demo-load is labelled review-only.
  • User control: Retune taste (fresh), usual week in Profile, New week / regenerate, discard capture, remove recipe, sign out, swap, collection add/remove. No unpublish (intentional, one-way globe). No revoke-link UI (sketch has revoke; Design/proto omit it — acceptable if receive is view-only and tokens are unguessable; still worth a later line).
  • Admin philosophy: No admin workbench, no queue. Matches decision log / PRD “no moderation queue for V1.”
  • Paywall: none.
  • Persona: Home Cook Planner is the generate/shop path; Recipe Collector is empty-Box + Browse + collections. Group Cook’s named circle is gone — link share replaces it.
